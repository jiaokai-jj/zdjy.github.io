> - **本目录只放完整版**（升级目标）。精简版只在论坛压缩包里，不放在这里，避免同名文件互相覆盖。
> - **升级触发条件**：精简版本地版本号 < 服务器 version.txt（当前 1006）才会弹升级。建议精简版设为 1004、完整版 1006（已部署）。

## 服务器文件（GitHub Pages 自定义域名: www.jyt.cc.cd/stocklinker/）
## 仓库: github.com/jiaokai-jj/zdjy.github.io

| 文件 | 说明 |
|------|------|
| version.txt | 纯数字版本号，如: 1002（新版本号必须大于旧版本号） |
| 随便恋.exe | 客户端程序 |
| codes.txt | 股票代码映射表 |
| software_config.ini | 软件配置文件 |

## 升级逻辑（已实现）

1. 客户端启动后 3 秒，后台线程自动 HTTP GET `https://www.jyt.cc.cd/stocklinker/version.txt`
2. 如果服务器版本号 > 本地版本号（APP_VERSION），弹出升级提示对话框
3. 用户点击"是"后，后台线程下载以下文件到 `.new` 临时文件：
   - 随便恋.exe.new
   - codes.txt.new
   - software_config.ini.new
4. 下载完成后生成 `update.bat` 批处理脚本
5. 程序退出，`update.bat` 等待进程结束后替换文件并重启程序

## 发布新版本步骤

1. 修改 `Utils.h` 中的 `APP_VERSION`（如 1002 → 1003）
2. 编译生成新的 `随便恋.exe`（运行 build.bat，输出 app_tmp.exe，重命名为 随便恋.exe）
3. 将以下文件复制到 `stocklinker/` 目录：
   - 随便恋.exe
   - codes.txt（如有更新）
   - software_config.ini（如有更新）
4. 修改 `version.txt` 为新版本号
5. Git commit & push 到 GitHub

## 版本号规则

- 纯数字递增：1000, 1001, 1002, ...
- 客户端通过 `APP_VERSION` 常量记录本地版本
- 服务器通过 `version.txt` 记录最新版本
- 只有 服务器版本 > 本地版本 时才提示升级
